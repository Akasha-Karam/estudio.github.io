1. Particiones y sistemas de ficheros

Un sistema de ficheros (filesystem) es la estructura que define cómo se organizan y se accede a los datos en los dispositivos de almacenamiento: establece cómo se guardan los ficheros, carpetas, enlaces, permisos, etc. Sin un sistema de ficheros los discos serían solo un espacio en bruto sin ninguna manera de identificar los contenidos.

Discos y particiones

Un disco es un dispositivo físico de almacenamiento. Una partición es una subdivisión lógica de un disco físico, definida en una tabla de particiones. El disco es el soporte físico, la partición es una división del disco, y el filesystem es la manera como se gestionan los ficheros dentro de esa partición.

En GNU/Linux, todo es un archivo. Cada partición se identifica como un dispositivo dentro de /dev:

  • /dev/sda1, /dev/sda2 — discos SATA, SCSI, USB
  • /dev/nvme0n1p1 — discos NVMe
  • /dev/mmcblk0p1 — tarjetas SD / memoria extraíble
  • /dev/hdX — discos IDE antiguos
Idea clave

Todo dispositivo de bloque en Linux aparece en /dev/. Los discos se nombran como sdX (SATA/SCSI/USB) o nvmeXnYpZ (NVMe), y sus particiones llevan un número al final: /dev/sda1, /dev/sda2…

1.1 MBR vs GPT

CaracterísticaMBRGPT
Año1983 (MS-DOS)Moderno
Particiones primariasMáximo 4Hasta 128
Máximo disco2 TBSin límite práctico
Copia seguridadNoSí (tabla duplicada)
GUID únicoNoSí (128 bits)
Boot sector

MBR almacena la tabla de particiones en el primer sector del disco (Boot Sector). GPT utiliza copias de seguridad de la tabla de particiones para mayor seguridad.

1.2 Gestionar particiones MBR con fdisk

fdisk es la herramienta clásica para gestionar tablas de particiones MBR.

fdisk
# fdisk /dev/sda
  m — muestra la ayuda
  p — muestra la tabla de particiones actual
  n — crea una nueva partición
  d — elimina una partición
  t — cambia el tipo
  w — guarda los cambios
  q — sale sin guardar
Atención

Los cambios no se aplican hasta que escribes w.

Tipos de particiones MBR:

  • Primary — máximo 4.
  • Extended — contiene varias particiones lógicas (logical).

Ejemplo: crear una partición con fdisk

$ sudo fdisk /dev/sdb

Comando (m para ayuda): n
Tipo de partición: primary
Número de partición (1-4): 1
Primer sector (2048-16777215): [Enter]
Último sector: +500M

Comando (m para ayuda): w
La tabla de particiones ha sido modificada.

Tras crear la partición, se podrá formatear con mkfs.

1.3 Gestionar particiones GPT con gdisk

gdisk es como fdisk pero para discos GPT.

gdisk
# gdisk /dev/sdb
  p — muestra las particiones
  n — crea nueva partición
  d — elimina
  s — ordena
  r — menú de recuperación
  w — guarda los cambios
Atención

Los cambios no se aplican hasta que escribes w.

1.4 Crear sistemas de ficheros con mkfs

Después de particionar, hay que formatear cada partición con un sistema de ficheros.

ext2 / ext3 / ext4

# mkfs.ext4 /dev/sdb1
# mke2fs -t ext4 /dev/sdb1

# Opciones útiles:
  -b       — tamaño de bloque
  -c       — comprueba bloques defectuosos
  -L       — etiqueta del volumen
  -n       — simulación sin escribir

XFS

# mkfs.xfs /dev/sda1

# Opciones:
  -b size=4096   — tamaño del bloque
  -L label       — etiqueta
  -N             — modo simulación

VFAT / FAT32

# mkfs.vfat /dev/sdc1

# Opciones:
  -F 32     — selecciona FAT32
  -n NAME   — etiqueta

exFAT

# mkfs.exfat /dev/sdb1

# Opciones:
  -i VOL_ID   — ID del volumen
  -n NAME     — nombre del volumen
¿Qué sistema elegir?

ext4 es el estándar en Linux: maduro, estable y con gran compatibilidad. XFS es ideal para ficheros muy grandes y alto rendimiento. Btrfs ofrece funcionalidades avanzadas como snapshots y compresión.

1.5 Swap

La swap no es un sistema de ficheros tradicional, sino un área del disco que el sistema utiliza como memoria virtual cuando la RAM se agota. Esto permite continuar trabajando aunque la memoria física esté llena, aunque con un rendimiento más lento.

# Crear una partición swap
# mkswap /dev/sda2
# swapon /dev/sda2

# Ver swap activa
# swapon --show
# free -h
Regla de oro

La swap suele configurarse como el doble de la RAM en servidores, o 2-4 GB en equipos de escritorio. Con SSD, la swap es bastante usable como alternativa a quedarse sin memoria.

1.6 Btrfs

Btrfs es un sistema de ficheros moderno con características avanzadas:

  • Soporte multi-dispositivo (RAID, mirroring, etc.)
  • Subvolúmenes y snapshots
  • Compresión automática (zlib, lzo, zstd)
# Crear un sistema de ficheros Btrfs
# mkfs.btrfs /dev/sdb1
# mkfs.btrfs /dev/sdb1 -L "NewDisk"

# Crear un subvolumen
# btrfs subvolume create /mnt/disk/BKP

# Crear un snapshot
# btrfs subvolume snapshot /mnt/disk /mnt/disk/snap
Ventaja de Btrfs

Los snapshots permiten revertir el sistema a un estado anterior en segundos. Muy útil antes de hacer cambios arriesgados.

1.7 La herramienta parted

parted puede hacerlo todo (particiones + formateo), pero con más riesgo si no se va con cuidado. A diferencia de fdisk y gdisk, parted aplica los cambios inmediatamente.

parted
# parted /dev/sdb
  print              — muestra información del disco
  mklabel gpt|msdos  — crea una tabla nueva
  mkpart primary ext4 1MiB 100MiB  — crea una partición
  rm 2               — elimina la partición 2
  resizepart 3 350MiB — redimensiona
  rescue START END   — intenta recuperar
parted

parted aplica los cambios inmediatamente, sin necesidad de escribir w. ¡Cuidado!

Notas finales
  • Los comandos mkfs crean sistemas de ficheros, no particiones.
  • fdisk y gdisk modifican la tabla de particiones.
  • parted puede hacerlo todo, pero con más riesgo.
  • Haz siempre copia de seguridad antes de modificar particiones.

2. RAID

2.1 ¿Qué es RAID?

RAID (Redundant Array of Independent Disks) es una técnica que permite combinar varios discos físicos (o virtuales) para conseguir:

  • Más velocidad (striping) ⏱️
  • Más seguridad / redundancia (mirroring, paridad) 🛟
  • O una combinación de ambas

Los tres pilares del RAID

  1. Striping — divide los datos entre discos → + velocidad, pero ninguna seguridad.
  2. Mirroring — copia exacta del disco → + seguridad, pero gasta más espacio.
  3. Paridad — guarda información de corrección para reconstruir datos si un disco falla.
Idea clave

RAID no es una copia de seguridad. Si borras un archivo por error, se borra en todos los discos del array. RAID protege contra fallos de disco, no contra errores humanos.

2.2 Cuadro comparativo RAID

RAIDQué haceLecturaEscrituraRedundanciaMín. discos
0Striping⭐⭐⭐⭐⭐⭐❌ ninguna2
1Mirroring⭐⭐⭐⭐⭐⭐ (1 disco)2
5Striping + Paridad⭐⭐⭐⭐⭐⭐ (1 disco)3
6Striping + doble paridad⭐⭐⭐⭐⭐⭐⭐ (2 discos)4
10Mirroring + Striping⭐⭐⭐⭐⭐⭐⭐⭐ (1 por pareja)4
RAID 10 — lo mejor de ambos

RAID 10 combina mirroring (RAID 1) y striping (RAID 0): primero crea pares de discos en espejo, luego divide los datos entre los pares. Ofrece velocidad y redundancia a la vez, pero necesita al menos 4 discos.

2.3 mdadm — gestionar RAIDs en Linux

mdadm es la herramienta que gestiona RAIDs en Linux.

Instalación
$ sudo apt install mdadm

Comandos principales:

  • mdadm --create — crear arrays RAID
  • mdadm --stop — parar arrays
  • mdadm --detail — ver qué tienes montado
  • mdadm --zero-superblock — borrar metadatos

Crear RAID 0

$ sudo ./fada_dels_discos.sh disc_0
$ sudo ./fada_dels_discos.sh disc_1
$ sudo mdadm --create /dev/md0 --level=0 \
    --raid-devices=2 /dev/loop5 /dev/loop6

Crear RAID 1

$ sudo mdadm --create /dev/md1 --level=1 \
    --raid-devices=2 /dev/loop7 /dev/loop8

Crear RAID 5

$ sudo mdadm --create /dev/md5 --level=5 \
    --raid-devices=3 /dev/loop9 /dev/loop10 /dev/loop11

Crear RAID 6

$ sudo mdadm --create /dev/md6 --level=6 \
    --raid-devices=4 /dev/loop12 /dev/loop13 /dev/loop14 /dev/loop15

Crear RAID 10

$ sudo mdadm --create /dev/md10 --level=10 \
    --raid-devices=4 /dev/loop16 /dev/loop17 /dev/loop18 /dev/loop19

Detener un RAID

$ sudo umount /dev/md0
$ sudo mdadm --stop /dev/md0
mdadm: stopped /dev/md0
Persistencia

Los arrays RAID creados con mdadm no son persistentes tras reinicio a menos que se guarden en /etc/mdadm/mdadm.conf: sudo mdadm --detail --scan >> /etc/mdadm/mdadm.conf

2.4 Loop devices

Los loop devices (como /dev/loop5) son archivos que se comportan como si fueran discos de verdad. Son perfectos para practicar RAID sin destruir nada real.

  • Funcionan igual que un disco: se les pueden hacer particiones y formatos.
  • Desaparecen cuando los desmontas o borras el archivo.
  • Son perfectos para hacer prácticas seguras.
Arrays

El array es el «disco virtual grande» que resulta de combinar varios discos pequeños. Aparece como /dev/md0, /dev/md1, etc. Sobre ese /dev/mdX es donde harás la tabla de particiones, crearás sistemas de ficheros y montarás directorios.

3. La Fada de los Discos

La fada_dels_discos.sh es una herramienta Unix-style minimalista que:

  • Crea discos virtuales como ficheros dispersos (*.disk)
  • Los convierte en loop devices (/dev/loopX)
  • De manera simple, clara y Unix-friendly

Invocar la fada

$ wget -q https://raw.githubusercontent.com/sjornetc/aux/main/fada_dels_discos.sh
$ chmod +x fada_dels_discos.sh

Uso básico

$ sudo ./fada_dels_discos.sh -s 1G unicorn
🧚‍♀ Creado el archivo «unicorn.disk» (tamaño 100M)
🧚‍♀ Loop creado! disc_0.disk -> /dev/loop7

Opciones

OpciónDescripción
-s, --size TAMAÑOTamaño del disco (1G, 200M, 128k)
-q, --quietSilencia logs; stdout solo contiene /dev/loopX
--helpMuestra ayuda
--versionMuestra versión (2.2.0), autora y licencia

¿Qué puedes hacer con los discos mágicos?

  • Crear particiones (fdisk)
  • Crear sistemas de ficheros (mkfs.ext4)
  • Montarlos (mount)
  • Usarlos en RAIDs (mdadm)
  • Experimentar sin miedo a estropear nada

Limpiar

$ sudo umount /mnt/unicorn
$ sudo losetup -d /dev/loop7
$ rm unicorn.disk
Prácticas seguras

Usa siempre loop devices con la Fada para practicar. Nunca trabajes directamente sobre discos reales con datos importantes.

4. FileNest

FileNest es una herramienta que crea o elimina una estructura de carpetas y ficheros simulando una casa.

Uso
filenest [OPCIONES] [PATH]

Opciones:
  -b, --build       Crea la estructura
  -d, --delete      Elimina la estructura
  -r, --replace     Si la carpeta existe, la elimina y la recrea
  -h, --help        Muestra la ayuda

Ejemplos:
  filenest -b                  → construye la casa en ./house
  filenest -br ~/projects/home → reconstruir la casa allí
  filenest -d                  → elimina ./house

Para ejecutar directamente desde el repositorio de GitHub:

bash <(wget -qO- https://raw.githubusercontent.com/sjornetc/filenest/main/run.sh) [OPCIONES] [PATH]

5. Usuarios y grupos en Linux

Gestión de usuarios y grupos en Linux (RA1 107.1).

Comandos básicos

ComandoDescripción
useradd nombreCrea un usuario
usermod -aG grupo nombreAñade usuario a un grupo
userdel nombreElimina un usuario
passwd nombreCambia la contraseña
groupadd nombreCrea un grupo
groups nombreMuestra los grupos de un usuario
id nombreMuestra UID, GID y grupos

Ficheros importantes

  • /etc/passwd — usuarios del sistema
  • /etc/shadow — contraseñas cifradas
  • /etc/group — grupos del sistema
Seguridad

Las contraseñas se almacenan cifradas en /etc/shadow, no en /etc/passwd. El fichero /etc/passwd es legible por todos los usuarios del sistema.

6. Permisos en Linux

Gestión de permisos de ficheros y directorios (RA1 104.5).

Tipos de permisos

PermisoFicheroDirectorio
r (4)LeerListar contenido
w (2)EscribirCrear/eliminar ficheros
x (1)EjecutarAcceder (entrar)

Comandos

# Cambiar permisos (modo octal)
chmod 755 script.sh
chmod u+x script.sh

# Cambiar propietario
chown usuario:grupo fichero

# Mostrar permisos
ls -l

Ejemplo de permisos

$ ls -l script.sh
-rwxr-xr-x 1 ana alumnos 1024 jun 5 10:00 script.sh
#  ^^^       ^   ^
#  |         |   └── grupo propietario (alumnos)
#  |         └────── usuario propietario (ana)
#  └─────────────── permisos: u=rwx, g=r-x, o=r-x

$ chmod 755 script.sh   # = rwxr-xr-x
$ chmod u+x script.sh   # añade ejecución al usuario
Permisos especiales

SUID (4xxx): el fichero se ejecuta con los permisos del propietario. SGID (2xxx): el fichero se ejecuta con los permisos del grupo. Sticky bit (1xxx): solo el propietario puede borrar sus ficheros (típico en /tmp).

7. Logs del sistema

Gestión de registros del sistema (RA1 108.2).

rsyslog

Sistema de logging tradicional. Las configuraciones se encuentran en /etc/rsyslog.conf y /etc/rsyslog.d/.

# Ficheros de log habituales
/var/log/syslog      — mensajes del sistema
/var/log/auth.log    — autenticaciones
/var/log/kern.log    — mensajes del kernel

systemd-journald

Sistema de logging moderno de systemd.

# Ver logs
journalctl
journalctl -u servicio    — logs de un servicio concreto
journalctl -f             — modo follow (tiempo real)
journalctl --since "1 hour ago"
journalctl vs rsyslog

journald guarda los logs en formato binario (más eficiente) mientras que rsyslog los guarda en texto plano. Muchos sistemas usan ambos: journald para consultas recientes y rsyslog para persistencia.

8. SSH / OpenSSH

Configuración y uso de SSH para acceso remoto seguro (RA1 110.3).

Conexión básica

ssh usuario@servidor
ssh -p 2222 usuario@servidor    — puerto personalizado

Claves SSH (autenticación sin contraseña)

# Generar clave
ssh-keygen -t rsa -b 4096

# Copiar clave pública al servidor
ssh-copy-id usuario@servidor

# Ficheros importantes:
~/.ssh/id_rsa          — clave privada
~/.ssh/id_rsa.pub      — clave pública
~/.ssh/authorized_keys — claves autorizadas en el servidor

Configuración del servidor (/etc/ssh/sshd_config)

Port 22
PermitRootLogin no
PasswordAuthentication yes/no
PubkeyAuthentication yes
Seguridad SSH

Deshabilita PasswordAuthentication yes y usa solo claves públicas para servidores expuestos a internet. Cambia el puerto 22 por uno no estándar para reducir ataques automatizados.

Túnel SSH (port forwarding)

# Local → Remoto: acceso a servicio remoto desde local
ssh -L 8080:localhost:80 usuario@servidor

# Remoto → Local: exponer servicio local al remoto
ssh -R 8080:localhost:3000 usuario@servidor

Útil para acceder a bases de datos o servicios detrás de un firewall.

9. Scripting en Linux

Creación de scripts de shell (RA1 105.2).

Estructura básica

#!/bin/bash
# Mi primer script

echo "¡Hola, mundo!"

# Variables
NOMBRE="Ana"
echo "Hola, $NOMBRE"

# Leer entrada
read -p "¿Cómo te llamas? " USUARIO
echo "Hola, $USUARIO"

Condicionales

if [ "$NOMBRE" = "Ana" ]; then
    echo "Eres Ana"
elif [ "$NOMBRE" = "Pedro" ]; then
    echo "Eres Pedro"
else
    echo "No te conozco"
fi

Bucles

# for
for i in {1..5}; do
    echo "Iteración $i"
done

# while
CONT=0
while [ $CONT -lt 5 ]; do
    echo $CONT
    ((CONT++))
done

Funciones

saludar() {
    echo "¡Hola, $1!"
}

saludar "Ana"
Consejo

Recuerda dar permisos de ejecución al script: chmod +x script.sh

Script completo: copia de seguridad

#!/bin/bash
# backup.sh — Copia de seguridad de un directorio

ORIGEN="$1"
DESTINO="$2"
FECHA=$(date +%Y%m%d_%H%M%S)

if [ -z "$ORIGEN" ] || [ -z "$DESTINO" ]; then
    echo "Uso: $0 <origen> <destino>"
    exit 1
fi

tar -czf "${DESTINO}/backup_${FECHA}.tar.gz" "$ORIGEN"
echo "Backup creado: ${DESTINO}/backup_${FECHA}.tar.gz"

10. Ejercicios resueltos

Intenta resolverlos antes de mirar la solución.

Ejercicio 1 — Crear partición y formatear

Crea un disco virtual de 500 MB con la Fada, particiónalo con una única partición usando fdisk, formatea como ext4 y móntalo en /mnt/midisco.

Ver solución 
$ sudo ./fada_dels_discos.sh -s 500M midisco
$ sudo fdisk /dev/loopX   # ← usar el loop device que devuelva la Fada
  n → primary → 1 → Enter → Enter → w

$ sudo mkfs.ext4 /dev/loopXp1
$ sudo mkdir -p /mnt/midisco
$ sudo mount /dev/loopXp1 /mnt/midisco
$ df -h /mnt/midisco

Ejercicio 2 — RAID 1 con loop devices

Crea dos discos virtuales de 200 MB cada uno, crea un RAID 1 con mdadm, formatea como ext4 y móntalo.

Ver solución 
$ sudo ./fada_dels_discos.sh -s 200M disco1
$ sudo ./fada_dels_discos.sh -s 200M disco2

$ sudo mdadm --create /dev/md0 --level=1 \
    --raid-devices=2 /dev/loop5 /dev/loop6

$ sudo mkfs.ext4 /dev/md0
$ sudo mkdir -p /mnt/raid1
$ sudo mount /dev/md0 /mnt/raid1

# Comprobar estado
$ sudo mdadm --detail /dev/md0

Ejercicio 3 — Script de backup

Crea un script que haga una copia de seguridad comprimida de un directorio, con nombre que incluya la fecha, y que borre backups de más de 7 días.

Ver solución 
#!/bin/bash
ORIGEN="$1"
DESTINO="${2:-/tmp/backups}"
FECHA=$(date +%Y%m%d)

mkdir -p "$DESTINO"
tar -czf "${DESTINO}/backup_${FECHA}.tar.gz" "$ORIGEN"

# Borrar backups de más de 7 días
find "$DESTINO" -name "backup_*.tar.gz" -mtime +7 -delete

echo "✅ Backup creado: ${DESTINO}/backup_${FECHA}.tar.gz"

Ejercicio 4 — Usuarios y permisos

Crea un usuario llamado invitado, créele un grupo invitados, asigna el usuario al grupo, y crea un directorio compartido /compartido con permisos 770 y grupo invitados.

Ver solución 
$ sudo groupadd invitados
$ sudo useradd -m -g invitados invitado
$ sudo passwd invitado
$ sudo mkdir /compartido
$ sudo chgrp invitados /compartido
$ sudo chmod 770 /compartido
$ ls -ld /compartido
# drwxrwx--- 2 root invitados 4096 ...

Ejercicio 5 — SSH sin contraseña

Configura acceso SSH por claves a un servidor remoto. Genera un par de claves RSA de 4096 bits y copia la clave pública al servidor.

Ver solución 
# En el cliente
$ ssh-keygen -t rsa -b 4096
$ ssh-copy-id usuario@servidor-remoto

# Probar conexión (ya no pide contraseña)
$ ssh usuario@servidor-remoto

# Para más seguridad, en el servidor:
$ sudo sed -i 's/^#PasswordAuthentication yes/PasswordAuthentication no/' \
    /etc/ssh/sshd_config
$ sudo systemctl restart sshd
