1. ¿Qué es Spring Boot?

Spring Boot es un framework de Java pensado para construir aplicaciones web (sobre todo APIs) de forma rápida y con muy poca configuración. Imagina que Spring "normal" te pide montar tú mismo todas las piezas (servidor, conexión a base de datos, seguridad…). Spring Boot ya viene con todas esas piezas ensambladas: tú solo te preocupas de la lógica de tu aplicación.

¿Qué ventajas tiene?

  • Servidor incrustado: incluye Tomcat dentro, no necesitas instalarlo.
  • Auto-configuración: detecta las librerías que añades y las configura solas.
  • Starters: dependencias agrupadas (ej. spring-boot-starter-web) que añaden todo lo necesario para una funcionalidad.
  • Producción real: métricas, health-checks y logs integrados.
Idea clave: Spring Boot = Spring + configuración automática + servidor incrustado. Tu proyecto es un .jar ejecutable: con java -jar mi-app.jar ya lo tienes corriendo.

Lenguaje y versión

En estos apuntes usaremos Java 17 y Spring Boot 3.2. Java 17 es la versión LTS (soporte largo) más usada hoy y Spring Boot 3 requiere mínimo Java 17.

3. API REST: conceptos básicos

Una API REST es una manera estándar de comunicar dos programas a través de HTTP. Tú haces una petición a una URL, y el servidor te responde con datos (normalmente en formato JSON).

REST = Representational State Transfer. Es un estilo de arquitectura: cada recurso (un usuario, un libro, un pedido…) tiene su URL, y los verbos HTTP indican qué quieres hacer.

3.1 Verbos HTTP

VerboSignificadoEjemplo
GETPedir datos (leer)GET /api/libros → lista libros
POSTCrear un recurso nuevoPOST /api/libros → añade un libro
PUTModificar uno existentePUT /api/libros/5 → actualiza el libro 5
DELETEBorrarDELETE /api/libros/5 → borra el libro 5

3.2 Códigos de estado

Cuando el servidor te responde, además de los datos manda un número que indica si todo ha ido bien o ha fallado algo:

CódigoSignificado
200 OKTodo correcto
201 CreatedHas creado un recurso nuevo
204 No ContentOK pero sin datos en la respuesta
400 Bad RequestEl cliente ha enviado datos mal
401 UnauthorizedFalta autenticarse
403 ForbiddenEstás autenticado pero no tienes permisos
404 Not FoundEl recurso no existe
500 Internal Server ErrorHa petado el servidor

3.3 Tu primer Controller

En Spring Boot, los controllers son las clases que reciben las peticiones HTTP. Para crearlas usamos anotaciones (cosas que empiezan por @):

Ejemplo: Hola Mundo

package com.estudio.demo.controller;

import org.springframework.web.bind.annotation.*;

@RestController                      // ← esta clase responde con JSON
@RequestMapping("/api")              // ← todas las URLs empiezan por /api
public class HolaController {

    @GetMapping("/hola")             // ← GET /api/hola
    public String hola() {
        return "¡Hola desde Spring Boot!";
    }

    @GetMapping("/hola/{nombre}")    // ← variable en la URL
    public String holaPersonal(@PathVariable String nombre) {
        return "¡Hola, " + nombre + "!";
    }
}

Al arrancar la aplicación (./mvnw spring-boot:run) y entrar en el navegador a http://localhost:8080/api/hola/Marta, verás:

¡Hola, Marta!

Anotaciones que aparecen aquí

  • @RestController: marca la clase como un controller que devuelve datos (no páginas HTML).
  • @RequestMapping("/api"): prefijo común para todas las URLs.
  • @GetMapping("/hola"): este método responde al verbo GET en esa ruta.
  • @PathVariable: coge una parte de la URL y la mete en una variable.

Ejemplo: recibir datos con POST

@PostMapping("/saludo")
public String saludar(@RequestBody Map<String, String> body) {
    String nombre = body.get("nombre");
    return "Encantado, " + nombre + "!";
}

Petición desde Postman:

POST http://localhost:8080/api/saludo
Content-Type: application/json

{ "nombre": "Aitor" }
Encantado, Aitor!
¿Qué es JSON? Es un formato de texto para representar datos: parejas "clave": valor entre llaves. Es lo que se manda y se recibe en una API REST.

4. Spring Data JPA: hablar con la base de datos

Para guardar datos necesitamos una base de datos. Spring Data JPA es una capa por encima de Hibernate que te permite hacer CRUD (Crear, Leer, Actualizar, Borrar) sin escribir SQL. Tú defines clases Java, y JPA crea las tablas y traduce los métodos a SQL.

4.1 Entidad

Una entidad es una clase Java que representa una tabla de la base de datos. Cada atributo = una columna.

Ejemplo: entidad Libro

package com.estudio.demo.entity;

import jakarta.persistence.*;
import lombok.*;

@Entity                              // ← es una entidad JPA
@Table(name = "libros")              // ← tabla "libros"
@Data                                // ← Lombok: getters/setters/toString
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class Libro {

    @Id                              // ← clave primaria
    @GeneratedValue(strategy = GenerationType.IDENTITY) // auto-incremental
    private Long id;

    @Column(nullable = false, length = 100)
    private String titulo;

    @Column(nullable = false)
    private String autor;

    private Integer anyo;
}

Al arrancar la app, Hibernate ejecutará algo como:

CREATE TABLE libros (
    id     BIGINT       AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(100) NOT NULL,
    autor  VARCHAR(255) NOT NULL,
    anyo   INT
);

4.2 Repository

El repository es la interfaz que te permite acceder a la BD. Lo más asombroso: tú solo declaras la interfaz, ¡Spring escribe la implementación!

Ejemplo

package com.estudio.demo.repository;

import com.estudio.demo.entity.Libro;
import org.springframework.data.jpa.repository.JpaRepository;
import java.util.List;

public interface LibroRepository extends JpaRepository<Libro, Long> {

    // Spring lee el nombre del método y genera la SQL solo:
    List<Libro> findByAutor(String autor);
    // → SELECT * FROM libros WHERE autor = ?

    List<Libro> findByAnyoGreaterThan(int anyo);
    // → SELECT * FROM libros WHERE anyo > ?
}
Query derivation: Spring Data deriva la SQL del nombre del método. findByX, findByXAndY, existsByX, countByX… son automáticos.

JpaRepository ya te trae gratis estos métodos:

MétodoQué hace
save(libro)INSERT o UPDATE
findById(id)SELECT por id
findAll()Devuelve todos
deleteById(id)DELETE por id
count()Cuenta filas

4.3 Service y Controller juntos

Para mantener el código ordenado, separamos en capas:

  • Controller — recibe peticiones HTTP.
  • Service — lógica de negocio.
  • Repository — habla con la BD.

LibroService.java

package com.estudio.demo.service;

import com.estudio.demo.entity.Libro;
import com.estudio.demo.repository.LibroRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
@RequiredArgsConstructor
public class LibroService {

    private final LibroRepository repo;   // Spring lo inyecta solo

    public List<Libro> listar()              { return repo.findAll(); }
    public Libro      crear(Libro l)         { return repo.save(l); }
    public Libro      buscar(Long id)        { return repo.findById(id).orElseThrow(); }
    public void       borrar(Long id)        { repo.deleteById(id); }
}

LibroController.java

package com.estudio.demo.controller;

import com.estudio.demo.entity.Libro;
import com.estudio.demo.service.LibroService;
import lombok.RequiredArgsConstructor;
import org.springframework.http.*;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/api/libros")
@RequiredArgsConstructor
public class LibroController {

    private final LibroService service;

    @GetMapping
    public List<Libro> listar() {
        return service.listar();
    }

    @GetMapping("/{id}")
    public Libro uno(@PathVariable Long id) {
        return service.buscar(id);
    }

    @PostMapping
    public ResponseEntity<Libro> crear(@RequestBody Libro l) {
        return ResponseEntity.status(HttpStatus.CREATED).body(service.crear(l));
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> borrar(@PathVariable Long id) {
        service.borrar(id);
        return ResponseEntity.noContent().build();
    }
}

5. DTOs y validación

Un DTO (Data Transfer Object) es una clase que sirve solo para transportar datos entre el cliente y el servidor. ¿Por qué no usar directamente la entidad?

  • La entidad puede tener campos que no queremos exponer (ej. contraseña).
  • Los datos que el cliente envía no siempre son iguales a los que guardamos.
  • Permite validar los datos antes de tocarlos.

DTO con validación

import jakarta.validation.constraints.*;
import lombok.Data;

@Data
public class LibroDTO {

    @NotBlank(message = "El título es obligatorio")
    @Size(min = 2, max = 100)
    private String titulo;

    @NotBlank
    private String autor;

    @Min(value = 1000, message = "Año demasiado antiguo")
    @Max(value = 2100)
    private Integer anyo;
}

Uso en el Controller

@PostMapping
public ResponseEntity<Libro> crear(@Valid @RequestBody LibroDTO dto) {
    Libro l = Libro.builder()
                   .titulo(dto.getTitulo())
                   .autor(dto.getAutor())
                   .anyo(dto.getAnyo())
                   .build();
    return ResponseEntity.status(HttpStatus.CREATED).body(service.crear(l));
}

Si mandas datos incorrectos:

POST /api/libros
{ "titulo": "", "autor": "x", "anyo": 800 }
HTTP 400 Bad Request { "titulo": "El título es obligatorio", "anyo": "Año demasiado antiguo" }
AnotaciónValidación
@NotBlankNo null, no vacío, no solo espacios
@NotNullNo null
@Size(min, max)Tamaño de String o lista
@EmailFormato de email válido
@Min / @MaxValor numérico mínimo/máximo
@Pattern(regex)Expresión regular

6. Spring Security con JWT

Hasta ahora cualquiera podía llamar a nuestra API. Vamos a protegerla. Para ello usaremos Spring Security + JWT.

6.1 ¿Qué es un JWT?

Un JWT (JSON Web Token) es una "cadenita" de texto firmada digitalmente que el servidor te da cuando te logueas correctamente. A partir de ese momento, en cada petición tú le mandas ese token y el servidor sabe quién eres sin necesidad de guardar nada (es stateless).

Tiene 3 partes separadas por puntos, en Base64:

eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJyb2dlciIsImV4cCI6MTcwMDB9.SflKxwRJSMeKKF2QT4fwpM
ParteContieneEjemplo
HeaderAlgoritmo de firma{"alg":"HS256","typ":"JWT"}
PayloadDatos del usuario (claims){"sub":"roger","exp":1700000000}
SignatureFirma con clave secretaHMAC-SHA256(header+payload, secret)
ATENCIÓN: el payload está en Base64, NO cifrado. Cualquiera puede leerlo. Por eso nunca metas contraseñas ni datos sensibles dentro. La firma solo garantiza que nadie lo ha modificado.

6.2 Flujo de autenticación

  1. El usuario manda POST /api/auth/login con su usuario y contraseña.
  2. El servidor comprueba en la BD que la contraseña es correcta.
  3. Si lo es, genera un JWT con sus datos (usuario, rol, caducidad) y lo devuelve.
  4. El cliente guarda el token y lo manda en cada petición en la cabecera Authorization: Bearer <token>.
  5. En cada petición, un filtro en el servidor lee el token, comprueba la firma y, si es válido, deja pasar la petición.
Sesiones vs JWT (stateless): con sesiones el servidor guarda un registro en memoria por cada usuario logueado. Con JWT no guarda nada: toda la información va dentro del token, firmada. Eso permite escalar horizontalmente (cualquier servidor puede validar cualquier token).

6.3 BCrypt: hash de contraseñas

Las contraseñas nunca se guardan en texto plano. Usamos BCrypt, un algoritmo que las convierte en un hash imposible de revertir:

passwordEncoder.encode("secret")
// → "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"
  • Unidireccional: no se puede recuperar la contraseña original.
  • Con salt aleatorio: dos contraseñas iguales dan hashes distintos.
  • Lento a propósito: dificulta ataques de fuerza bruta.

Para comparar la contraseña que envía el usuario en el login:

passwordEncoder.matches("secret", hashGuardadoEnBD)
// → true o false

Paso 3 — Entidad User y rol

public enum Role { USER, ADMIN }
@Entity
@Table(name = "users")
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class User implements UserDetails {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String username;

    @Column(unique = true, nullable = false)
    private String email;

    @Column(nullable = false)
    private String password;     // hash BCrypt

    @Enumerated(EnumType.STRING)

    @Override public boolean isAccountNonLocked()      { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled()               { return true; }
}

Paso 6 — JwtService (genera/valida tokens)

@Service
public class JwtService {

    @Value("${jwt.secret}")     private String secretKey;
    @Value("${jwt.expiration}") private long jwtExpiration;

    public String extractUsername(String token) {
        return extractClaim(token, Claims::getSubject);
    }

    public String generateToken(UserDetails u) {
        return Jwts.builder()
                .subject(u.getUsername())
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + jwtExpiration))
                .signWith(getSigningKey())
                .compact();
    }

    public boolean isTokenValid(String token, UserDetails u) {
        String username = extractUsername(token);
        return username.equals(u.getUsername()) && !isTokenExpired(token);
    }

    private boolean isTokenExpired(String token) {
        return extractClaim(token, Claims::getExpiration).before(new Date());
    }

    private <T> T extractClaim(String token, Function<Claims, T> resolver) {
        Claims claims = Jwts.parser()
                .verifyWith(getSigningKey()).build()
                .parseSignedClaims(token).getPayload();
        return resolver.apply(claims);
    }

    private SecretKey getSigningKey() {
        byte[] keyBytes = Decoders.BASE64.decode(secretKey);
        return Keys.hmacShaKeyFor(keyBytes);
    }
}

Paso 7 — JwtFilter (intercepta cada petición)

@Component
@RequiredArgsConstructor
public class JwtFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest req,
                                    HttpServletResponse res,
                                    FilterChain chain)
            throws ServletException, IOException {

        String authHeader = req.getHeader("Authorization");

        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            chain.doFilter(req, res); return;
        }

        String jwt      = authHeader.substring(7);
        String username = jwtService.extractUsername(jwt);

        if (username != null &&
            SecurityContextHolder.getContext().getAuthentication() == null) {

            UserDetails user = userDetailsService.loadUserByUsername(username);

            if (jwtService.isTokenValid(jwt, user)) {
                var authToken = new UsernamePasswordAuthenticationToken(
                        user, null, user.getAuthorities());
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
        chain.doFilter(req, res);
    }
}

Paso 8 — ApplicationConfig (beans)

@Configuration
@RequiredArgsConstructor
public class ApplicationConfig {

    private final UserRepository userRepository;

    @Bean
    public UserDetailsService userDetailsService() {
        return username -> userRepository.findByUsername(username)
                .orElseThrow(() -> new UsernameNotFoundException("Usuario no encontrado"));
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public AuthenticationProvider authenticationProvider() {
        var provider = new DaoAuthenticationProvider();
        provider.setUserDetailsService(userDetailsService());
        provider.setPasswordEncoder(passwordEncoder());
        return provider;
    }
}

Paso 9 — SecurityConfig (reglas)

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtFilter jwtFilter;
    private final AuthenticationProvider authProvider;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .anyRequest().authenticated()
            )
            .sessionManagement(s ->
                s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authenticationProvider(authProvider)
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration cfg)
            throws Exception {
        return cfg.getAuthenticationManager();
    }
}

Paso 10 — AuthService (lógica de registro/login)

@Service
@RequiredArgsConstructor
public class AuthService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtService jwtService;
    private final AuthenticationManager authenticationManager;

    public AuthResponse register(RegisterRequest r) {
        if (userRepository.existsByUsername(r.getUsername()))
            throw new IllegalArgumentException("El usuario ya existe");

        User user = User.builder()
                .username(r.getUsername())
                .email(r.getEmail())
                .password(passwordEncoder.encode(r.getPassword()))
                .role(Role.USER)
                .build();

        userRepository.save(user);
        return new AuthResponse(jwtService.generateToken(user));
    }

    public AuthResponse login(LoginRequest r) {
        authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                r.getUsername(), r.getPassword()));

        User user = userRepository.findByUsername(r.getUsername()).orElseThrow();
        return new AuthResponse(jwtService.generateToken(user));
    }
}

Ejercicio 2 — CRUD de Películas

Crea un CRUD completo para una entidad Pelicula con los campos: id, titulo, director, anyo, nota (de 0 a 10). Endpoints: listar, ver por id, crear, actualizar, borrar.

Ver solución

Pelicula.java

@Entity @Table(name = "peliculas")
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class Pelicula {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(nullable = false) private String titulo;
    private String director;
    private Integer anyo;
    private Double  nota;
}

PeliculaRepository.java

public interface PeliculaRepository
        extends JpaRepository<Pelicula, Long> { }

PeliculaController.java

@RestController
@RequestMapping("/api/peliculas")
@RequiredArgsConstructor
public class PeliculaController {

    private final PeliculaRepository repo;

    @GetMapping
    public List<Pelicula> listar() { return repo.findAll(); }

    @GetMapping("/{id}")
    public Pelicula uno(@PathVariable Long id) {
        return repo.findById(id)
                .orElseThrow(() -> new ResponseStatusException(
                        HttpStatus.NOT_FOUND, "No encontrada"));
    }

    @PostMapping
    public ResponseEntity<Pelicula> crear(@RequestBody Pelicula p) {
        return ResponseEntity.status(HttpStatus.CREATED).body(repo.save(p));
    }

    @PutMapping("/{id}")
    public Pelicula actualizar(@PathVariable Long id, @RequestBody Pelicula p) {
        p.setId(id);
        return repo.save(p);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> borrar(@PathVariable Long id) {
        repo.deleteById(id);
        return ResponseEntity.noContent().build();
    }
}

Ejercicio 4 — Validación

Convierte el endpoint POST /api/libros para que use un DTO con validación: el título debe tener entre 2 y 100 caracteres y el año debe estar entre 1000 y 2100.

Ver solución 
@Data
public class LibroDTO {
    @NotBlank @Size(min = 2, max = 100) private String titulo;
    @NotBlank                           private String autor;
    @Min(1000) @Max(2100)               private Integer anyo;
}

@PostMapping
public ResponseEntity<Libro> crear(@Valid @RequestBody LibroDTO dto) {
    Libro l = Libro.builder()
                  .titulo(dto.getTitulo())
                  .autor(dto.getAutor())
                  .anyo(dto.getAnyo())
                  .build();
    return ResponseEntity.status(HttpStatus.CREATED).body(repo.save(l));
}
POST /api/libros { "titulo": "x", "autor": "", "anyo": 500 } → 400 Bad Request { "titulo": "size must be between 2 and 100", "autor": "must not be blank", "anyo": "must be greater than or equal to 1000" }
