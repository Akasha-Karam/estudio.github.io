1. Unity

1.1 ¿Qué es Unity?

Unity es un motor de videojuegos (game engine) multiplataforma: un programa que te da todas las piezas necesarias para hacer un juego — render 3D/2D, físicas, audio, animación, UI, input… — y tú solo escribes la lógica en C#.

Con Unity puedes publicar el mismo proyecto en muchas plataformas:

  • PC: Windows, macOS, Linux.
  • Móvil: Android, iOS.
  • Consolas: Switch, PlayStation, Xbox.
  • Web: WebGL (juega en el navegador).
  • VR/AR: Quest, Vision Pro, etc.
Idea clave (analogía con Spring Boot)

Si vienes de Spring Boot, piensa en Unity como un framework parecido: en Spring tú no montas el servidor, solo escribes @RestController y Spring se encarga del resto. En Unity tú no programas el render ni las físicas, solo escribes scripts (MonoBehaviour) que Unity engancha automáticamente a los objetos de la escena.

1.2 Unity Hub

Unity Hub es la aplicación que gestiona tus proyectos y las versiones de Unity. Es como SDK Manager + Android Studio Welcome Screen juntos.

  1. Descarga Unity Hub.
  2. Inicia sesión con una cuenta Unity (la versión Personal es gratis).
  3. En la pestaña Installs, instala una versión LTS (Long Term Support), por ejemplo 2022.3.x LTS.
  4. En la pestaña Projects, pulsa New project, elige una plantilla (3D Core, 2D Core, etc.) y un nombre.
Usa siempre LTS

Las versiones LTS son las estables, las que se actualizan durante 2 años con bugfixes. Las versiones "Tech" son novedades pero traen bugs. Para aprender y para proyectos serios: LTS.

Cuando creas un proyecto, Unity genera muchas carpetas. La única que importa al día a día es Assets/: todo lo que pongas ahí dentro forma parte del juego (scripts, sprites, modelos, sonidos, escenas…).

Tabs y arrastrar

Cada panel es una pestaña que puedes arrastrar por su título a otra zona del editor para reorganizar tu espacio. Si la sueltas fuera del editor, se convierte en una ventana flotante (útil con dos monitores).

La barra de herramientas arriba tiene los botones ▶ Play, ⏸ Pause y ⏭ Step. Al pulsar Play, Unity arranca la escena (como mvn spring-boot:run, pero en directo dentro del editor).

¡Cuidado con Play!

Mientras estás en modo Play, los cambios que hagas en el Inspector no se guardan. Si modificas valores y luego sales de Play, todo vuelve a como estaba. Para experimentar con valores definitivos: sal de Play primero.

2. GameObjects y Components

El modelo mental de Unity es muy simple, pero importante entenderlo:

  • Una escena contiene GameObjects.
  • Cada GameObject es solo un contenedor — no hace nada por sí mismo.
  • Lo que hace que un GameObject sea algo (cubo, cámara, enemigo, botón…) son los Components que tiene pegados.

2.1 ¿Qué es un GameObject?

Un GameObject es cualquier "cosa" en la escena: el suelo, el personaje, la cámara, una luz, un enemigo, un UI. Es básicamente un nodo con nombre, posición (Transform) y una lista de componentes.

GameObject vs Spring Bean

Un GameObject es como un bean de Spring, y los Components pegados son sus interfaces implementadas. La diferencia es que en Unity tú los compones arrastrando en el Inspector, no con @Autowired.

2.2 Components

Un Component es una "pieza" que añade comportamiento o datos a un GameObject. Unity trae muchos de fábrica:

ComponentPara qué
TransformPosición, rotación y escala. Todos los GameObjects lo tienen, no se puede quitar.
MeshRendererHace que el objeto se vea (dibuja el modelo 3D).
SpriteRendererDibuja un sprite (2D).
Collider (Box, Sphere, Mesh…)Da forma "física" para detectar colisiones.
RigidbodyHace que el objeto reaccione a la física (gravedad, fuerzas).
CameraConvierte un GameObject en la cámara que renderiza la escena.
LightEmite luz.
AudioSourceReproduce sonido.
AnimatorControla animaciones.
Tus scripts MonoBehaviourTu lógica de juego.

Para añadir un component: selecciona el GameObject en el Hierarchy y pulsa Add Component al final del Inspector.

2.3 Transform

El Transform guarda la posición, rotación y escala del GameObject, y forma parte del árbol jerárquico (un objeto puede ser hijo de otro y moverse con él).

Ejemplo: mover algo por código

Assets/Scripts/EjemploTransform.cs
using UnityEngine;

public class EjemploTransform : MonoBehaviour
{
    void Start()
    {
        // Posición absoluta
        transform.position = new Vector3(0f, 1f, 0f);

        // Mover relativo (añade al actual)
        transform.Translate(Vector3.forward * 2f);

        // Rotar 90º sobre el eje Y
        transform.Rotate(0f, 90f, 0f);

        // Escalar al doble
        transform.localScale = new Vector3(2f, 2f, 2f);
    }
}
Vector3

Vector3 es una tripleta (x, y, z). En 2D solo se usan x e y. Atajos típicos:

  • Vector3.zero = (0,0,0)
  • Vector3.one = (1,1,1)
  • Vector3.up / down / left / right / forward / back

3. Scripts (MonoBehaviour)

La forma de meter tu lógica en el juego es crear una clase que herede de MonoBehaviour y pegarla a un GameObject como componente. Unity llamará automáticamente a los métodos especiales (Start, Update…) en el momento adecuado.

3.1 Crear un script

  1. En el panel Project, click derecho → Create → C# Script.
  2. Ponle nombre, por ejemplo Jugador. El nombre del fichero debe coincidir con el nombre de la clase.
  3. Arrástralo encima de un GameObject del Hierarchy (o pulsa Add Component → Jugador).
  4. Haz doble click para abrirlo en Visual Studio o Rider.
Assets/Scripts/Jugador.cs
using UnityEngine;

public class Jugador : MonoBehaviour
{
    void Start()
    {
        Debug.Log("¡Hola Unity!");
    }

    void Update()
    {
        // Se ejecuta una vez por frame (~60 veces por segundo)
    }
}
El script SOLO se ejecuta si está pegado a un GameObject

Crear el archivo .cs no es suficiente. Tienes que arrastrarlo a un GameObject (o usar Add Component). Si no, no pasa nada al darle a Play. Es parecido a registrar un @Component de Spring: no basta con tener la clase, hay que ponerla en el contexto.

3.2 Ciclo de vida de un MonoBehaviour

Unity llama a estos métodos en este orden. No los llamas tú: los implementas y Unity los invoca. Es como las anotaciones de ciclo de vida de Spring (@PostConstruct, @PreDestroy).

MétodoCuándo se llamaPara qué
Awake()Al crear el objeto, antes que nada.Inicializar referencias internas (GetComponent).
OnEnable()Cada vez que el objeto se activa.Suscribirse a eventos.
Start()Antes del primer frame (después de Awake de todos).Setup que depende de otros objetos.
Update()Una vez por frame.Input, movimiento no físico, lógica de juego.
FixedUpdate()A intervalos fijos (50 veces/s por defecto).Físicas (mover Rigidbody, aplicar fuerzas).
LateUpdate()Después de Update de todos.Cámara que sigue al jugador.
OnDisable()Al desactivar el objeto.Desuscribirse de eventos.
OnDestroy()Al destruirse.Limpiar recursos.
Awake vs Start

Awake se llama al instante al crearse el objeto. Start se llama justo antes del primer Update. En Awake aún puede que otros objetos no estén listos. Regla práctica: en Awake haces GetComponent de tu propio GameObject; en Start haces referencias a OTROS GameObjects.

Update vs FixedUpdate

Si mueves un objeto con físicas (Rigidbody), hazlo en FixedUpdate. Si lo mueves "a mano" (cambiando transform.position), puedes hacerlo en Update pero multiplica por Time.deltaTime para que la velocidad no dependa de los FPS.

3.3 [SerializeField] y campos públicos

Para que un valor de tu script aparezca en el Inspector y se pueda editar sin tocar código, hay dos formas:

Assets/Scripts/Jugador.cs
using UnityEngine;

public class Jugador : MonoBehaviour
{
    // OPCIÓN A: campo público (no recomendado: rompe encapsulación)
    public float velocidad = 5f;

    // OPCIÓN B: campo privado + [SerializeField] (recomendado)
    [SerializeField] private float vida = 100f;

    // No aparece en el Inspector (privado sin SerializeField)
    private float tiempoVivo;

    void Update()
    {
        tiempoVivo += Time.deltaTime;
        transform.Translate(Vector3.forward * velocidad * Time.deltaTime);
    }
}
Analogía con Spring

[SerializeField] es el equivalente a marcar un campo para que Spring lo inyecte: tú declaras qué necesita el script y luego, en el Inspector, lo "inyectas" arrastrando el GameObject u objeto adecuado. Es DI visual.

3.4 GetComponent y referencias a otros objetos

Para hablar con otro componente del mismo GameObject (o de otro):

Assets/Scripts/Jugador.cs
using UnityEngine;

public class Jugador : MonoBehaviour
{
    private Rigidbody rb;                           // componente del MISMO GameObject
    [SerializeField] private Transform enemigo;     // referencia inyectada en el Inspector

    void Awake()
    {
        // Buscar un componente en este mismo GameObject
        rb = GetComponent<Rigidbody>();
    }

    void Update()
    {
        // Distancia al enemigo
        float dist = Vector3.Distance(transform.position, enemigo.position);
        Debug.Log($"Distancia: {dist}");
    }
}

Formas de conseguir una referencia, de mejor a peor:

  1. [SerializeField] y arrastrar en el Inspector — la mejor, lo ves en el editor.
  2. GetComponent<T>() — para componentes del mismo GameObject.
  3. GetComponentInChildren<T>() / InParent — para hijos o padres.
  4. FindObjectOfType<T>() — lento, evítalo en Update.
  5. GameObject.Find("Nombre") — frágil (busca por nombre, si lo renombras se rompe).

4. Input del jugador

4.1 Input Manager (clásico)

El sistema antiguo (pero más sencillo para empezar) lee teclado, ratón y mando con la clase Input. Está siempre disponible.

LlamadaQué devuelve
Input.GetKey(KeyCode.W)true mientras esté pulsada.
Input.GetKeyDown(KeyCode.Space)true SOLO el frame en que se pulsa.
Input.GetKeyUp(KeyCode.Space)true SOLO el frame en que se suelta.
Input.GetAxis("Horizontal")float entre -1 y 1 (A/D, flechas, stick).
Input.GetAxisRaw("Vertical")Igual pero sin suavizado (-1, 0 o 1).
Input.GetMouseButtonDown(0)true al pulsar click izquierdo.
Input.mousePositionPosición del ratón en píxeles.

4.2 Mover un personaje con WASD

Ejemplo: movimiento básico en plano (estilo Kitchen Chaos)

Assets/Scripts/JugadorMovimiento.cs
using UnityEngine;

public class JugadorMovimiento : MonoBehaviour
{
    [SerializeField] private float velocidad = 5f;

    void Update()
    {
        // Lee dirección desde teclado (-1, 0, 1)
        float x = Input.GetAxisRaw("Horizontal");  // A/D, flechas izquierda/derecha
        float z = Input.GetAxisRaw("Vertical");    // W/S, flechas arriba/abajo

        Vector3 direccion = new Vector3(x, 0f, z).normalized;

        // Mover, multiplicando por deltaTime → independiente de los FPS
        transform.position += direccion * velocidad * Time.deltaTime;

        // Mirar hacia donde va, si se está moviendo
        if (direccion != Vector3.zero)
        {
            transform.forward = direccion;
        }
    }
}
¿Por qué * Time.deltaTime?

Time.deltaTime es el tiempo que ha pasado desde el frame anterior (en segundos). Multiplicando por él, "velocidad" pasa a ser unidades por segundo en lugar de "unidades por frame". Sin esto, en un PC potente el personaje iría 3x más rápido que en uno lento.

5. Físicas y colisiones

5.1 Rigidbody

El componente Rigidbody hace que el GameObject reaccione a la física: gravedad, fuerzas, choques. Sin Rigidbody, un objeto con Collider es estático (paredes, suelo).

PropiedadSignificado
MassMasa en kg.
Use GravitySi le afecta la gravedad.
Is KinematicSi está activado, el Rigidbody no se mueve por física. Tú lo mueves con transform.
DragResistencia al movimiento (frenado).
ConstraintsBloquear ejes (útil para 2.5D).

Ejemplo: saltar al pulsar espacio

Assets/Scripts/Salto.cs
using UnityEngine;

[RequireComponent(typeof(Rigidbody))]   // obliga a tener Rigidbody
public class Salto : MonoBehaviour
{
    [SerializeField] private float fuerzaSalto = 7f;
    private Rigidbody rb;

    void Awake()
    {
        rb = GetComponent<Rigidbody>();
    }

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
        {
            // Empuja hacia arriba instantáneamente
            rb.AddForce(Vector3.up * fuerzaSalto, ForceMode.Impulse);
        }
    }
}

5.2 Colliders

El Collider define la "forma" sólida del objeto. Tipos principales:

  • BoxCollider — caja. Rápido, ideal para suelos y cajas.
  • SphereCollider — esfera.
  • CapsuleCollider — pastilla, perfecta para personajes.
  • MeshCollider — sigue la malla 3D. Caro, solo para escenarios.
  • En 2D: BoxCollider2D, CircleCollider2D, PolygonCollider2D…
Regla del Rigidbody en colisiones

Para que dos objetos choquen y se detecte la colisión, al menos uno de los dos debe tener Rigidbody. Si los dos son colliders sin Rigidbody (paredes), no pasa nada al "tocarse".

Eventos de colisión (los implementas en un script del objeto que choca):

Assets/Scripts/Bala.cs
void OnCollisionEnter(Collision col)
{
    Debug.Log("Choqué con: " + col.gameObject.name);
    Destroy(gameObject);   // se destruye al chocar
}

void OnCollisionStay(Collision col) { /* mientras siguen chocando */ }
void OnCollisionExit(Collision col) { /* al separarse */ }

5.3 Triggers (sensores)

Si marcas la casilla "Is Trigger" de un Collider, el objeto deja de ser sólido y pasa a ser un sensor: detecta cuando algo entra o sale, pero no le frena. Perfecto para zonas (zona de daño, puerta automática, ítem que se recoge…).

Assets/Scripts/Moneda.cs
using UnityEngine;

public class Moneda : MonoBehaviour
{
    void OnTriggerEnter(Collider otro)
    {
        if (otro.CompareTag("Player"))
        {
            Debug.Log("¡Moneda recogida!");
            Destroy(gameObject);
        }
    }
}
Tags

Un tag es una etiqueta de texto que puedes asignar a un GameObject en lo alto del Inspector. Sirve para identificarlo sin depender del nombre. Usa CompareTag("Player") en lugar de gameObject.tag == "Player" (es más rápido).

6. Prefabs

Un prefab es una "plantilla" de GameObject guardada como asset. Si arrastras el mismo prefab 50 veces a la escena, tienes 50 copias conectadas a la plantilla: si cambias el prefab, todas las copias se actualizan.

Analogía

Un prefab es como una clase: la plantilla es la clase, los GameObjects en la escena son las instancias. En Spring sería la diferencia entre la clase UserService (definición) y el bean concreto que vive en el contexto.

6.1 Crear un prefab

  1. Construye el GameObject en la escena (con sus components y valores).
  2. Arrástralo desde el Hierarchy a una carpeta del panel Project (típicamente Assets/Prefabs/).
  3. El GameObject del Hierarchy se vuelve azul → ahora es una instancia del prefab.
  4. Doble click en el prefab para editarlo en modo aislado.

6.2 Instantiate y Destroy

Para crear copias de un prefab en tiempo de ejecución (balas, enemigos, partículas…):

Assets/Scripts/Pistola.cs
using UnityEngine;

public class Pistola : MonoBehaviour
{
    [SerializeField] private GameObject balaPrefab;
    [SerializeField] private Transform puntoDisparo;
    [SerializeField] private float velocidadBala = 20f;

    void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            // Crear una bala en el punto de disparo, mirando hacia delante
            GameObject bala = Instantiate(balaPrefab,
                                          puntoDisparo.position,
                                          puntoDisparo.rotation);

            // Empujarla hacia delante
            Rigidbody rb = bala.GetComponent<Rigidbody>();
            rb.velocity = puntoDisparo.forward * velocidadBala;

            // Auto-destruir a los 3 segundos
            Destroy(bala, 3f);
        }
    }
}
Destroy(this) vs Destroy(gameObject)

Destroy(this) elimina solo el script. Para borrar el GameObject entero usa Destroy(gameObject).

7. Escenas

Una escena (archivo .unity) es un nivel del juego: contiene todos los GameObjects de un momento (menú principal, nivel 1, nivel 2, pantalla de game over…). Solo hay una escena cargada a la vez (salvo carga aditiva).

7.1 SceneManager

Para cargar otra escena por código:

Assets/Scripts/MenuPrincipal.cs
using UnityEngine;
using UnityEngine.SceneManagement;   // ← necesario

public class MenuPrincipal : MonoBehaviour
{
    public void Jugar()
    {
        SceneManager.LoadScene("Nivel1");   // por nombre
        // o por índice: SceneManager.LoadScene(1);
    }

    public void Salir()
    {
        Application.Quit();   // cierra el juego (solo en build, no en el editor)
    }
}
Build Settings

Para poder cargar una escena por nombre o índice, primero hay que añadirla en File → Build Settings → Scenes In Build. Si no está ahí, da error en tiempo de ejecución.

7.2 DontDestroyOnLoad

Por defecto, al cambiar de escena, todos los GameObjects se destruyen. Si quieres que algo persista (música de fondo, gestor de partida…):

Assets/Scripts/Musica.cs
void Awake()
{
    DontDestroyOnLoad(gameObject);
}

8. UI (Canvas)

8.1 Canvas y EventSystem

Toda la UI vive dentro de un GameObject especial llamado Canvas. Cuando creas el primer elemento de UI (GameObject → UI → Button), Unity crea automáticamente:

  • Canvas — el "lienzo" donde se pinta la UI.
  • EventSystem — gestiona los clicks y la navegación con teclado/mando. Sin él, los botones no responden.

El Canvas tiene tres modos de render:

Render ModeCuándo usarlo
Screen Space - OverlayUI pegada a la pantalla (lo más común: HUD, menús).
Screen Space - CameraUI ligada a una cámara concreta (para efectos).
World SpaceUI dentro del mundo 3D (cartel sobre la cabeza de un personaje).

8.2 Botones, textos y listeners

Un botón se enlaza a un método público de un script de dos formas: desde el Inspector o desde código.

Opción A: desde el Inspector

  1. Crea un script con un método público (public void OnJugar()).
  2. Pégaselo a un GameObject de la escena.
  3. Selecciona el botón → en su componente Button, sección On Click (), pulsa "+".
  4. Arrastra el GameObject que tiene el script al hueco.
  5. En el desplegable, elige NombreScript → OnJugar().

Opción B: desde código

Assets/Scripts/MenuUI.cs
using UnityEngine;
using UnityEngine.UI;
using TMPro;   // si usas TextMeshPro (recomendado)

public class MenuUI : MonoBehaviour
{
    [SerializeField] private Button btnJugar;
    [SerializeField] private TextMeshProUGUI txtPuntuacion;
    private int puntos = 0;

    void Start()
    {
        btnJugar.onClick.AddListener(OnJugar);
        txtPuntuacion.text = "Puntos: 0";
    }

    void OnJugar()
    {
        puntos += 10;
        txtPuntuacion.text = $"Puntos: {puntos}";
    }
}
TextMeshPro

El componente Text clásico tiene tipografía borrosa. Usa TextMeshPro (GameObject → UI → Text - TextMeshPro): mucha mejor calidad, soporta efectos y es lo estándar moderno.

9. Animaciones y Audio

9.1 Animator

Las animaciones en Unity se controlan con dos cosas:

  • AnimationClip — la animación en sí (movimiento de un modelo, cambio de sprite…).
  • AnimatorController — una máquina de estados que decide qué clip se está reproduciendo, con transiciones entre ellos.

El flujo típico:

  1. Selecciona el personaje en la escena.
  2. Abre la ventana Window → Animation → Animator.
  3. Crea estados (Idle, Run, Jump) y transiciones.
  4. Define parámetros (bool isRunning, trigger jump).
  5. Desde el script, cambia los parámetros con SetBool, SetTrigger…
Assets/Scripts/JugadorAnim.cs
using UnityEngine;

public class JugadorAnim : MonoBehaviour
{
    private Animator animator;

    void Awake()
    {
        animator = GetComponent<Animator>();
    }

    void Update()
    {
        bool moviendose = Input.GetAxisRaw("Horizontal") != 0f
                       || Input.GetAxisRaw("Vertical")   != 0f;

        animator.SetBool("isRunning", moviendose);

        if (Input.GetKeyDown(KeyCode.Space))
            animator.SetTrigger("jump");
    }
}

9.2 AudioSource

Para reproducir un sonido:

  1. Añade el componente AudioSource a un GameObject.
  2. Asigna un AudioClip en el campo AudioClip.
  3. Marca Play On Awake si quieres que suene al cargar la escena (música de fondo) o llama tú a Play() desde código.
Assets/Scripts/Disparo.cs
using UnityEngine;

public class Disparo : MonoBehaviour
{
    [SerializeField] private AudioClip clipDisparo;
    private AudioSource audioSource;

    void Awake() { audioSource = GetComponent<AudioSource>(); }

    void Disparar()
    {
        // PlayOneShot permite solapar sonidos sin cortarse
        audioSource.PlayOneShot(clipDisparo);
    }
}

10. Patrones (estilo Kitchen Chaos)

El curso Kitchen Chaos de Code Monkey introduce tres patrones que aparecen en casi todos los proyectos Unity profesionales: Singleton, Events y ScriptableObject.

10.1 Singleton

Un Singleton es un objeto del que solo existe una instancia en toda la app. En Unity se usa para gestores únicos: GameManager, SoundManager, InputManager…

Es como un @Service de Spring

En Spring, @Service crea un bean único (por defecto). En Unity no hay esa magia: el patrón Singleton lo implementas tú.

Assets/Scripts/GameManager.cs
using UnityEngine;

public class GameManager : MonoBehaviour
{
    // Acceso global: GameManager.Instance.HacerAlgo();
    public static GameManager Instance { get; private set; }

    [SerializeField] private int vidas = 3;

    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);   // ya hay uno, este sobra
            return;
        }
        Instance = this;
        DontDestroyOnLoad(gameObject);
    }

    public void PerderVida()
    {
        vidas--;
        Debug.Log($"Te quedan {vidas} vidas");
    }
}

Desde cualquier otro script:

GameManager.Instance.PerderVida();

10.2 Events / Action (desacoplar código)

En lugar de que el jugador llame directamente a la UI ("UI, súmame un punto"), el jugador lanza un evento y quien quiera escuchar se suscribe. Igual que un ApplicationEventPublisher en Spring.

Assets/Scripts/Jugador.cs
using System;
using UnityEngine;

public class Jugador : MonoBehaviour
{
    // Evento sin parámetros
    public event Action OnSalto;

    // Evento con dato (cuántos puntos)
    public event Action<int> OnPuntuar;

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
            OnSalto?.Invoke();                  // notifica a todos los suscriptores

        if (Input.GetKeyDown(KeyCode.P))
            OnPuntuar?.Invoke(10);
    }
}
Assets/Scripts/UIPuntos.cs
using UnityEngine;
using TMPro;

public class UIPuntos : MonoBehaviour
{
    [SerializeField] private Jugador jugador;
    [SerializeField] private TextMeshProUGUI txt;
    private int total = 0;

    void OnEnable()  { jugador.OnPuntuar += SumarPuntos; }
    void OnDisable() { jugador.OnPuntuar -= SumarPuntos; }   // ¡siempre desuscribir!

    void SumarPuntos(int cuantos)
    {
        total += cuantos;
        txt.text = $"Puntos: {total}";
    }
}
Desuscríbete siempre

Si te suscribes a un evento (+=) y no te desuscribes (-=) al destruir el objeto, generas memory leaks. Patrón seguro: += en OnEnable, -= en OnDisable.

10.3 ScriptableObject

Un ScriptableObject es un asset reutilizable que guarda datos en disco — como un @ConfigurationProperties de Spring, pero editable visualmente. Perfecto para definir cosas como "tipos de enemigos", "armas", "recetas" sin meter constantes en código.

Assets/Scripts/RecetaSO.cs
using UnityEngine;

[CreateAssetMenu(fileName = "Receta", menuName = "Cocina/Receta")]
public class RecetaSO : ScriptableObject
{
    public string nombre;
    public Sprite icono;
    public int tiempoCoccion;
    public Ingrediente[] ingredientes;
}

Después, en el panel Project → click derecho → Create → Cocina → Receta. Cada asset .asset es una receta concreta (Hamburguesa, Ensalada, Pizza…). Los scripts apuntan a esas recetas con [SerializeField] private RecetaSO receta;.

Ventaja gorda

Cambias los valores de una receta sin tocar código y sin recompilar. Diseñadores y artistas pueden trabajar contigo sin pisarse.

11. Ejercicios

Ejercicio 1 — Cubo que cae

Crea una escena con un suelo (Plane) y un cubo encima a 5 unidades de altura. El cubo debe caer por gravedad y rebotar un poco al chocar con el suelo.

Ver solución
  1. GameObject → 3D Object → Plane — escálalo a (5, 1, 5).
  2. GameObject → 3D Object → Cube — ponlo en (0, 5, 0).
  3. En el cubo: Add Component → Rigidbody.
  4. Crea un Physic Material (click derecho en Project → Create → Physic Material), llámalo "Goma", pon Bounciness = 0.6.
  5. Arrastra "Goma" al campo Material del BoxCollider del cubo.
  6. Play. El cubo cae y rebota.

Ejercicio 2 — Mover con WASD y rotar al moverse

Crea un cubo y un script JugadorMovimiento que lo mueva con WASD a una velocidad configurable desde el Inspector. Debe mirar siempre hacia donde se mueve.

Ver solución
Assets/Scripts/JugadorMovimiento.cs
using UnityEngine;

public class JugadorMovimiento : MonoBehaviour
{
    [SerializeField] private float velocidad = 5f;

    void Update()
    {
        float x = Input.GetAxisRaw("Horizontal");
        float z = Input.GetAxisRaw("Vertical");
        Vector3 dir = new Vector3(x, 0, z).normalized;

        transform.position += dir * velocidad * Time.deltaTime;

        if (dir != Vector3.zero) transform.forward = dir;
    }
}

Pegar al cubo. Ajustar la velocidad en el Inspector.

Ejercicio 3 — Recoger monedas (Trigger)

Añade 5 cubos pequeños amarillos en la escena. Cuando el jugador los toca, desaparecen y suma 1 al contador. Muestra el contador en pantalla con un TextMeshProUGUI.

Ver solución

1) Crea un cubo "Moneda", márcale en BoxCollider → Is Trigger. Asígnale el tag "Coin".
2) Crea el prefab arrastrando "Moneda" a Assets/Prefabs/.
3) Asigna al jugador el tag "Player".

Assets/Scripts/Moneda.cs
public class Moneda : MonoBehaviour
{
    void OnTriggerEnter(Collider c)
    {
        if (c.CompareTag("Player"))
        {
            ContadorMonedas.Instance.Sumar();
            Destroy(gameObject);
        }
    }
}
Assets/Scripts/ContadorMonedas.cs
using UnityEngine;
using TMPro;

public class ContadorMonedas : MonoBehaviour
{
    public static ContadorMonedas Instance { get; private set; }

    [SerializeField] private TextMeshProUGUI txt;
    private int total = 0;

    void Awake() { Instance = this; }

    public void Sumar()
    {
        total++;
        txt.text = $"Monedas: {total}";
    }

4) Crea un Canvas + Text (TMP), arrástralo al campo txt.
5) Coloca varias instancias del prefab Moneda en la escena. Play.

Ejercicio 4 — Disparar balas (Instantiate + Rigidbody)

Al hacer click izquierdo, el jugador dispara una bala (prefab esférico con Rigidbody) que sale hacia delante. La bala se autodestruye a los 3 segundos o al chocar con algo.

Ver solución
Assets/Scripts/Pistola.cs
using UnityEngine;

public class Pistola : MonoBehaviour
{
    [SerializeField] private GameObject balaPrefab;
    [SerializeField] private Transform punto;
    [SerializeField] private float velocidad = 20f;

    void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            GameObject b = Instantiate(balaPrefab, punto.position, punto.rotation);
            b.GetComponent<Rigidbody>().velocity = punto.forward * velocidad;
            Destroy(b, 3f);
        }
    }
}
Assets/Scripts/Bala.cs
public class Bala : MonoBehaviour
{
    void OnCollisionEnter(Collision c) { Destroy(gameObject); }
}

Ejercicio 6 — Cambiar de escena con un botón

Crea dos escenas: Menu y Juego. En Menu pon un botón "Jugar" que cargue la escena Juego. En Juego pon un botón "Volver" que cargue Menu.

Ver solución

1) File → Build Settings → añade ambas escenas a "Scenes In Build".

Assets/Scripts/MenuUI.cs
using UnityEngine;
using UnityEngine.SceneManagement;

public class MenuUI : MonoBehaviour
{
    public void Jugar()  { SceneManager.LoadScene("Juego"); }
    public void Volver() { SceneManager.LoadScene("Menu"); }
}

2) Pega el script a un GameObject vacío en cada escena.
3) En cada botón: On Click () → "+" → arrastra el GameObject → elige MenuUI.Jugar (o Volver).

Las 7 reglas de oro de Unity
  1. Usa LTS. Nada de versiones Tech para aprender.
  2. El nombre del fichero = nombre de la clase. Si no, el script no se compila ni se puede pegar.
  3. Movimiento físico → FixedUpdate. Movimiento "a mano" → Update con Time.deltaTime.
  4. Sólido vs sensor: para chocar, ambos con Collider y al menos uno con Rigidbody. Para detectar paso, Is Trigger.
  5. Referencias en el Inspector mejor que Find. Es la "DI visual" de Unity.
  6. Suscríbete en OnEnable, desuscríbete en OnDisable. Evita memory leaks.
  7. Cuidado con Play: los cambios en Inspector mientras está en Play no se guardan.
